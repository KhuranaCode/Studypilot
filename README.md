# StudyPilot: AI-Powered Study Planner

> *"Plan Smarter. Study Better. Achieve More."*

StudyPilot is a production-grade, AI-driven study planning web application built with **React 18**, **TypeScript**, **Vite**, **Tailwind CSS**, **Firebase Authentication**, **Cloud Firestore**, and **Google Gemini AI**.

StudyPilot helps students organize course subjects, track deadlines, run focused Pomodoro/deep-work study sessions, and generate realistic, personalized, editable weekly study schedules that adapt to student workload and availability.

---

## 1. System Architecture & Features

### Visual Design System & Color Palette
StudyPilot features a cohesive, premium blue-and-lavender theme built on CSS custom properties and tailored Tailwind tokens:
* **Deep Blue (`#3D52A0`)**: Primary actions, active navigation states, strong headings, brand accents.
* **Periwinkle Blue (`#7091E6`)**: Progress rings, secondary buttons, interactive badges, active highlights.
* **Muted Blue (`#8697C4`)**: Supporting icons, secondary metric series, subtler typography.
* **Soft Lavender (`#ADBBDA`)**: Crisp card borders, dividers, subtle hover surfaces.
* **Pale Lavender (`#EDE8F5`)**: Background surfaces, spacious dashboard canvas, input backgrounds.

### Core Capabilities
* **User Authentication**: Secure Firebase Authentication supporting Email/Password and Google Sign-In with isolated student data.
* **Database & Data Isolation**: Cloud Firestore with strict user-scoped security rules (`request.auth.uid == userId`) ensuring students can only read, write, or modify their own data.
* **Deterministic AI Study Planner**:
  * Evaluates subject difficulty, upcoming exams, deadlines, priority, and daily capacity.
  * Server-side AI generation powered by Google Gemini 1.5 Flash with fallback to deterministic algorithmic scheduling.
  * Transparent badge indicator displaying whether the active plan was generated by **Google Gemini 1.5 Flash** or the **Smart Deterministic Engine**.
  * **Deterministic Schedule Validator**: Enforces availability windows, breaks between sessions, daily limit capping, rest-day respect, and flags unscheduled work.
* **Focus Timer with Timestamp Precision**:
  * Wall-clock timestamp tracking (`performance.now()` & `Date.now()`) resilient to browser tab background throttling.
  * Automatic `localStorage` session state recovery across page reloads.
  * Idempotency guards preventing duplicate session logging to Firestore.
* **Secure Administrator Portal (`/admin`)**:
  * Dedicated admin-only dashboard guarded by `AdminRoute.tsx` and server-side secret authorization.
  * System health telemetry (Gemini status, uptime, total registered accounts, aggregate study hours).
  * Privacy-preserving user directory: emails are masked (`a***n@domain.com`) and private student study notes/tasks are strictly isolated and never exposed.
  * Secure bootstrap procedure via `npm run admin:bootstrap`.

Create a `.env` file in the project root based on `.env.example`:

```bash
# ==============================================================================
# Client-Side Firebase Configuration (Exposed to browser via Vite VITE_ prefix)
# Obtain these from your Firebase Project Console -> Project Settings -> General
# ==============================================================================
VITE_FIREBASE_API_KEY="your_firebase_web_api_key"
VITE_FIREBASE_AUTH_DOMAIN="your_project_id.firebaseapp.com"
VITE_FIREBASE_PROJECT_ID="your_project_id"
VITE_FIREBASE_STORAGE_BUCKET="your_project_id.appspot.com"
VITE_FIREBASE_MESSAGING_SENDER_ID="your_sender_id"
VITE_FIREBASE_APP_ID="your_firebase_app_id"
VITE_FIREBASE_MEASUREMENT_ID="G-XXXXXXXXXX"

# Optional: Set to 'true' to connect to local Firebase Emulators
VITE_USE_FIREBASE_EMULATORS="false"

# ==============================================================================
# Server-Side Secrets (NEVER exposed to browser, Git, or client code)
# ==============================================================================
GEMINI_API_KEY="your_google_gemini_api_key_here"
```

> **Security Note:** The `GEMINI_API_KEY` is purely a server-side secret consumed by `server/aiBackendHandler.ts`. It does not have a `VITE_` prefix and is never bundled into the client build.

## 5. Firebase Configuration & Deployment

### Step 1: Firebase Project Setup
1. Go to the [Firebase Console](https://console.firebase.google.com/) and create a new project.
2. In the project dashboard, add a **Web Application**.
3. Copy the configuration credentials into your `.env` file (`VITE_FIREBASE_API_KEY`, etc.).

### Step 2: Enable Authentication Providers
1. Go to **Authentication** -> **Sign-in method**.
2. Enable **Email/Password**.
3. Enable **Google** (configure support email and save).

### Step 3: Enable Cloud Firestore
1. Go to **Firestore Database** -> **Create Database**.
2. Select your preferred region (e.g., `us-central1`).
3. Deploy the strict security rules in [firestore.rules](file:///home/aaaditya/my_projects/StudyPilot/firestore.rules):

```bash
# Install Firebase CLI if not already installed
npm install -g firebase-tools

# Login and deploy security rules
firebase login
firebase deploy --only firestore:rules
```

## 6. AI Integration & Server Deployment

### AI Provider & Model
* **Provider**: Google Gemini API
* **Model**: `gemini-1.5-flash` (balanced for fast structured response and high accuracy)
* **Obtaining API Key**:
  1. Go to [Google AI Studio](https://aistudio.google.com/).
  2. Click **Create API Key**.
  3. Set `GEMINI_API_KEY="AIzaSy..."` in your server environment or `.env`.

### Rate Limiting & Cost Safeguards
* **In-memory Rate Limiting**: Requests to `/api/ai/generate-plan` are throttled to a maximum of **15 generation requests per hour per user** to prevent quota exhaustion.
* **Payload Limits**: Requests are capped at 512KB.
* **Deterministic Fallback**: If the Gemini API key is not configured or the network is unavailable, the system automatically falls back to the deterministic algorithmic scheduler without failing the user's flow.
* **Expected Cost**: Gemini 1.5 Flash offers a generous free tier (up to 15 RPM). Paid tier pricing is approximately $0.075 per 1 million input tokens and $0.30 per 1 million output tokens (typically < $0.0005 per generated schedule).

### Production Server Options
1. **Cloud Functions for Firebase**: Export `handleAiPlanGenerationRequest` as an HTTP Cloud Function `exports.generatePlan = functions.https.onRequest(...)`.
2. **Node.js Express / Fastify Server**: Mount `handleAiPlanGenerationRequest` onto a `POST /api/ai/generate-plan` route.
3. **Containerized Deployment (Cloud Run / Vercel Serverless / Render)**: Store `GEMINI_API_KEY` in environment secrets.

## 7. Deterministic Schedule Validator

StudyPilot enforces a zero-trust model with respect to AI outputs. The AI model's response is treated as an initial proposal that passes through two layers of validation:

1. **Schema Validation (`Zod`)**: Ensures the model response adheres strictly to the `AiPlanResponseSchema` (title, summary, session list, timestamps in 24h format).
2. **Deterministic Constraint Engine (`src/services/scheduleValidator.ts`)**:
   * **Availability Check**: Rejects sessions on declared rest days or outside daily time windows.
   * **Boundary Enforcement**: Sessions cannot extend past the daily window closing time.
   * **Overlap Elimination**: Dynamically sequences overlapping sessions and inserts mandatory breaks (e.g. 5-15 mins).
   * **Daily Study Cap**: Caps daily totals to the user's configured daily maximum limit (e.g. 4 hours).
   * **Unscheduled Tasks Notice**: Explicitly reports any tasks that could not fit into the available capacity with clear actionable reasons.
   * **Preservation of Work**: Preserves already-completed focus sessions and prevents duplicate session logging.
